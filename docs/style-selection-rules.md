# 风格与画风选择规则

## 主画风

- 每条预设只保存一个主画风：写实、二维动漫或 3D。作品继续使用单选画风。
- 二维动漫的画法单选：赛璐璐、柔涂、水墨、复古手绘。
- 3D 的画法单选：动画电影、写实 CGI、风格化、黏土、低多边形。
- 切换主画风时确认清空原手写描述，并清除不适用的参数。
- 旧的多画风预设保留；编辑时必须明确选择一个主画风。在没有作品画风上下文的速创中禁止选择这种旧预设。
- 如果旧预设已被不同画风的作品使用，应先复制为各自独立的预设，再逐个替换作品引用，保留现有的在用画风保护。

## 全片参数

| 参数 | 规则 |
| --- | --- |
| 拍摄介质 | 单选；胶片与数字电影机分开 |
| 胶片型号 | 单选；只有胶片介质下可选 |
| 画幅质感 | 单选，与摄影机和胶片型号分开 |
| 颗粒强度 | 单选，包含无颗粒 |
| 质感效果 | 最多四项，可叠加光晕、柔焦、划痕等独立效果 |
| 主色调 | 单选；冷暖搭配可选青橙、冷阴影等组合色板，具体辅色可补充描述 |
| 对比强度 | 高、中、低单选 |
| 黑位 | 下沉、提亮单选 |
| 高光 | 柔和滚落、清晰利落单选 |
| 明暗曲线 | 单选，与对比强度分开 |
| 布光原则 | 单选；仅指定全片倾向，不指定正午、月光等具体场景条件 |
| 光学风格 | 变形宽银幕、复古球面、现代球面单选 |
| 影像年代、视觉参照 | 分成两个独立单选 |
| 主氛围 | 最多三项；明显相反的情绪给提醒，允许有意表达反差 |

强冲突在前后端均阻止保存，例如低对比与高反差黑白、漂白旁路同时指定。普通球面光学与变形镜头横向光晕也不可同时指定。

具体光源、时段、焦距、构图和运镜属于场景或分镜。全片参数不再提供这些选项。暖色与冷色、多个焦距在一部作品中并不天然互斥。

画风默认规则只约束二维、三维、实拍的边界，不强制鲜艳颜色、高对比或高复杂度建模，避免干扰复古动画、黏土和低多边形。

## 提示词与兼容

- 新风格默认使用参数模式。参数变化实时更新预览；保存时后端再次校验，并重新生成正文和画法，忽略客户端传入的旧正文。
- 动漫和 3D 画法进入人物、道具、场景、首帧和视频；整片质感只进入场景、首帧和视频，沿用现有范围。
- 参数模式不保存全片统一的“片段光影”。额外文字放在补充描述中，由用户维护语义一致性。
- 手写模式保留完整创作自由，仅使用手写正文。参数不作为生成依据，页面也不显示参数控件。自由文本不承诺自动识别所有语义冲突。
- 旧预设默认保持手写模式。已知参数可按维度重分组；冲突、多余项和自定义值在切换参数模式后明确显示，必须处理后才能保存，不截断用户旧数据。
- 官方预设保留经过撰写的手写正文，修正明显的介质与镜头混用，参数摘要只保留全片维度。手写预设详情不把参数摘要作为当前正文依据。

## 实现与验证

共享规则：`frontend/src/utils/styleParameterRules.json`。PHP 和 TypeScript 读取同一份目录，避免规则漂移。后端部署必须保留该 JSON 文件；现有 Docker 镜像会复制它。

数据库增加 `prompt_mode` 和 `prompt_extra`。风格管理接口会按现有方式自动补列；独立迁移可使用 `database/sql/20261015_style_parameter_rules.sql`，不要在已自动补列的数据库上重复执行。

验证命令：

```text
cd frontend
npm run type-check
npm run check:i18n
node scripts/test-style-parameters.cjs
cd ..
php scripts/test_series_style_prompt_rules.php
php scripts/test_style_parameter_rules.php
```

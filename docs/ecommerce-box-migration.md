# 电商宝盒迁移记录

日期：2026-10-21。状态：原生模块已实现，已完成本地隔离回归；尚未部署线上或进行真实付费生成验收。

## 已交付与运行方式

普通用户侧栏已新增“电商宝盒”，入口 `/admin/ecommerce-box`。页面沿用站内深色 UI，主入口只有商品图片和商品视频，新项目默认制作一张宣传海报。图片按“上传商品图 → 看一眼文案、按需修改 → 生成”完成；视频按“上传创作素材 → 识别用途 → 对话确认 → 满意后生成”完成。商品主图、详情套图、主图与详情和模特试穿收进“更多配置”的图片用途。上传图直接参与生成，无需先付费提取。试穿的模特只用一个下拉菜单，默认自动搭配成年虚拟模特，可选择上传、资产或单独生成参考图。

图片费用随输入自动预估，主按钮直接提交已报价的计划；视频必须先确认方案再确认实际视频费用。普通版显示积分，Official 标明预计费用与实际用量结算。断线重试保留原提交键及快照。结果、批次、暂停继续、改图、单项下载、整套 ZIP 下载、详情长图和保存资产均留在同页；套图改图按页替换显示，导出只使用对应计划的最新页面。“更多配置”在左侧创建栏原位展开，不打开设置抽屉或二级侧栏；额外付费操作单独确认费用。项目、素材及需求对话均按用户隔离，私有配置不加入共享 Skills 库。

图片使用现有 ToAPIs GPT Image 2.5 Flare/Sunburst 普通版与 Official 配置，视频使用现有 Seedance 2 配置。套图与多张输出拆成独立后台任务，普通/Official 参数分别校验，费用复用当前积分服务。提交时保存提示词、参考图顺序、页面规格和模型通道快照；模型通道变更后暂停该任务，防止在另一通道误提交或误查询。

项目表在首次 API 请求或 Worker 启动时通过幂等 SQL 建立：`database/sql/20261020_ecommerce_box.sql`。后台命令为 `php think ecommerce:worker --sleep=3`，单次检查为 `php think ecommerce:worker --once`。使用 Docker 的本地启动方式：

```powershell
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --no-deps ecommerce-worker
```

开发环境前端入口为 `http://127.0.0.1:5177/admin/ecommerce-box`，需普通用户登录。生产环境构建前端后启动/重启 PHP 与电商 Worker；systemd 模板部署需首次执行 `systemctl enable --now 'ai-workflow-worker@ecommerce:worker'`。部署交接脚本已将其加入后续重启列表。仅更新前端不能启动后台任务。

Docker Worker 使用 `www-data`，与 PHP-FPM 共用可写的 `public/storage` 和 `runtime`，避免后台或 CLI 创建的 root 目录阻断网页上传。旧数据卷若已有 root 目录，需修复这两个目录的归属后重新创建 Worker。手动运行检查也应使用服务默认账号，避免显式切回 root。

状态恢复只查询已经保存的上游任务。进程中断且未收到上游编号时，任务显示“待核对”，不自动再次发起付费请求；已明确失败的任务可由用户确认费用后重新生成。暂停/取消只影响尚未提交的项，已经提交的项仍查询到结束。

## 商品创作 Skills 与设置简化

电商宝盒与提示词助手共用平台内置目录。本次新增 6 个细分方法：商品棚拍与主图、商品材质与工艺、商品场景与使用展示、电商详情与海报版式、商品参考图转视频、生活种草与带货短片。来源版本、许可证和取舍见 `docs/prompt-skill-sources.md`。

`EcommerceSkills` 按目标、页面与视频方向从服务端白名单选取，实际规则编译进提示词再报价并冻结，不增加额外决策模型调用。私有 Skills 不进入电商共享目录；历史已提交任务仍执行原快照。视频默认商业展示，可显式改为生活种草，保留手写脚本；5 秒商业视频采用单镜头，10/15 秒按总时长分段。

默认创建区保留商品图、图片/视频两个入口、可编辑宣传文案、一句要求和生成按钮；选择模特试穿不会增加必填项。视频额外保留 5/10/15 秒时长以便评估费用，剧情想法可以直接输入或口述。视频先识别素材并通过必要问题确认需求，再给出一段成片方案；已识别且未变更的图片复用结果。分镜和人物在“查看剧情与人物”中按需打开，没有指定照片时按文字设定自动搭配。

“更多配置”在左栏原位展开，输出规格、场景、套图页面与文案、商品资料与处理默认折叠；桌面和手机均不使用配置侧栏。指定模特只用一个下拉菜单，不必先开启开关或逐项配置人物属性。单独制作人物照片仍是可选的付费操作，取消费用确认不会将剧情人物切换为等待图片的状态。自动模特成品在原始请求中保存 `autoModel` 标记，使后续微调从原成品继承人物，而不会误套用纯商品摄影的无人规则。

## 宣传图文案与排版

图片模式默认开启宣传文案。上传商品图或从资产添加商品后，缺少标题时自动调用 `POST /api/ecommerce/draft-copy`；打开历史项目和刷新页面不自动调用付费模型。主区域可修改标题、副标题和已有卖点，也可以关闭文案或手工填写。初次拟写失败时可以继续手工填写；点击生成仍缺少标题时先拟写，再确认图片费用。用户修改过输入或切换项目后，晚到的文案响应不覆盖当前内容。

服务端只使用当前用户可见的文本模型，优先使用支持看图的模型，并发送最多三张经素材权限校验的商品图。本地文件转换为最长边 1600px 的 JPEG 预览；文本模型未配置看图能力时只使用文字资料，并明确标记未分析图片。复用内置商品图片与详情版式方法，不匹配私有 Skills。标题最多 20 字、副标题 40 字、卖点最多三条且每条 16 字；没有依据的价格、功效、材质、认证和优惠不自动补造。

文案调用以 `ecommerce_copy` 记录并按现有文本 token 规则计费；请求键与输入哈希缓存成功结果，拒绝项目并发，格式错误最多修复一次，网络错误不自动重发。生成图片时冻结文案和风格快照；模型只生成商品底图，浏览器 Canvas 使用系统中文字体绘制标题、副标题和卖点，完整商品图置于文字区域下方。纯白首张主图 H1 和试穿默认不附文字。不同风格使用现有配色，文字和商品不互相覆盖。

成品可通过“改文案”修改或去掉文字，不重新请求生图模型；旧成品也可添加文案。修改按任务编号保存在用户私有项目的 `posterOverrides` 中。预览、单图、ZIP、详情长图使用相同排版；保存至资产会先上传排版成品，并校验与原任务属于同一用户及项目。项目仍保留原始底图，后续改图沿用当前文案。当前仅提供一套稳定的标题/商品/卖点版式，不保证原图中已有文字能被移除；跨域远程图片需提供可供浏览器读取的 CORS 响应，否则明确提示排版失败。

浏览器回归还覆盖上传后自动拟写、人工改字、标题像素、单图与 ZIP 的相同排版、保存资产、刷新保持及去掉文字；全部使用隔离夹具，未消耗真实模型额度。

## 剧情视频与人物

商品视频主区域不再要求选择展示或剧情模式。上传商品、人物或场景图后自动调用 `POST /api/ecommerce/brief-turn` 的 `analyze` 动作，先逐图识别用途。显式从图片切换视频时也会识别已有素材；打开或刷新历史项目只读取 `POST /api/ecommerce/brief`，不会自动调用付费模型。识别必须使用当前用户可见、明确配置图片输入能力的模型，不能用文本推断代替看图。未变化的素材按编号和 URL 复用识别，新图只分析新增部分。

剧情输入支持文字及浏览器 SpeechRecognition 口述转文字；仅安全上下文及支持该 API 的浏览器可用，需要麦克风权限。未接入服务端语音转写，实际识别服务由浏览器提供；不支持时保留文字输入。浏览器自动化以模拟识别事件验证文字落入输入框，不代表真实麦克风或语音服务已验收。

主按钮“完善视频方案”发送 `consult`，复用提示词助手文本客户端、内置商品视频、生活种草及分镜方法。模型结合识别结果、原始剧情、已回答问题、完整对话和明确时长，一次最多提出两个带互斥选项的问题，也可自由填写答案。人物图只识别外观，不猜身份；剧情角色出现后由用户下拉指定照片扮演谁。可修正图片用途或设为“不使用”。重复已回答的问题会触发格式修复；已有角色分配后不得偷偷更换角色编号和名称。

需求完整后返回一段自然语言成片方案、最多 4 个角色、5 个连续镜头和按人物归属的中文对白；5 秒以内只用一个连续镜头。时间从 0 严格连续到所选总时长，对白按镜头时长校验。超长对白要求模型压缩并提醒用户；功效、价格和促销不补造依据。用户可直接补充修改意见；点击“满意，生成视频”先以 `confirm` 保存确认版本，再显示实际费用对话框，最后确认才提交生成队列。返回新方案的请求不会自动触发确认或生成。

识别和需求对话单独记录为 `ecommerce_brief`，按现有文本 token 规则计费；格式错误最多修复一次，网络错误不自动重发。`ecommerce_brief_requests` 保存当前用户、项目、版本、请求键、输入哈希和完整对话状态，相同已完成请求只返回缓存，不再次请求或扣费。确认动作不调用模型、不产生 token 费用。相同请求键不能更换内容，旧版本与项目并发请求被拒绝；处理中不能删除项目。中断超过 300 秒后可明确发起新请求。旧 `expand-story` API 保留给已有调用者，电商页面改用新需求流程。

方案、分镜、角色和对话在原页保留；分镜只读，修改通过补充意见更新方案。每人默认自动搭配，可上传或单独生成人物照片；人物生图沿用图片报价和后台任务，确认费用后才提交，结果按角色 ID 和当时描述回填，旧结果不覆盖已修改设定。人物图片与商品参考分别传给视频模型，提示词写明参考图索引与角色身份，被忽略的图片不会传给模型。所有图片仍使用既有上传、导入和素材归属校验。

剧情文本、角色、照片和声音开关随项目保存，需求答案和对话单独按私有项目保存。修改剧情、时长、素材或相关参数后，必须更新方案并重新确认。服务端生成入口核验确认版本、时长、精确分镜和参考图集合，前端亦校验签名并按确认用途分离图片；历史冻结任务仍可显式重试。新增图片保留已有答案和未变更的角色分配。包含对白时自动开启声音。当前仍受视频模型单段 4 至 15 秒限制，未实现多段视频自动拼接，也未通过真实付费模型验收对白、口型或成片效果。

## 目标与结论

将桌面 `libtv` 的电商创作能力作为智梦工厂的原生功能接入，用户菜单新增“电商宝盒”，建议路由 `/admin/ecommerce-box`。复用当前登录、模型配置、积分、生成适配器、媒体存储和资产权限。

源项目：`C:/Users/YxonChan/Desktop/libtv`，包名 `ecom-box`，版本 `0.27.4`，调研提交 `cd22e30`。源项目为 Vue 3 + Vite + 自建 Node HTTP 服务；当前项目为 Vue 3 + TypeScript + Element Plus + ThinkPHP。双方均使用 Vue 3，业务组件和纯逻辑可迁移，不需要另设前端框架。

建议采用原生模块迁移。原项目的独立登录、Node 服务、全局浅色 CSS、文件任务存储不作为新模块的运行依赖。

## 必须处理的兼容问题

1. **数据归属。** 原项目只配置一个服务账户，浏览器 IndexedDB 使用固定的 `current` 工作区；接口任务以 UUID 和文件记录管理。新模块所有项目、素材、生成任务和导入操作都必须验证当前用户，不能把这些记录直接当作多用户数据。
2. **旧人脸审核。** 原 `buildVideoRequest` 强制要求模特审核通过并转成 `asset://`，后端也查询旧 private-avatar 接口。迁移后提交原始图片 URL，由当前视频适配器附加 `private_asset_review=true`。不移植旧检测按钮和审核阻断。
3. **生成参数。** 原图片服务默认 `gpt-image-2`，允许 `n=1/2/4`，使用固定像素到清晰度映射。当前 ToAPIs 2.5 普通版与 Official 参数不同，且每个上游任务 `n=1`，必须按模型转换，并把多张输出拆成任务。
4. **提示词长度。** 原套图单页校验允许 30,000 字，视频提交允许 10,000 字；当前速创入口最多 4,000 字。电商模块应有自己的参数与长度校验，调用现有生成适配器，不能直接转发到速创入口或静默截断。
5. **素材数量与路径。** 原项目每区最多上传 12 张，而当前速创最多引用 6 张。上传数量与实际提交数量要分别校验，超限需明确选择或拒绝。旧 `/examples`、`/scene-previews`、Data URL 等必须转换为新模块资源和受控存储地址，覆盖所有嵌套的原始请求及套图快照。
6. **任务恢复。** 原图片任务具备请求 ID 防重复与补下载机制，套图状态也区分未提交和结果未确认。迁移必须保留这些语义：先持久化任务和上游 ID，再轮询；刷新只查询原任务，结果未知时不自动重发付费生成。
7. **样式与类型。** 原 CSS 修改 `:root`、`body`、`button` 等全局元素，会覆盖站内样式；新模块使用独立容器和 scoped 样式。原 JavaScript 业务模块需要补齐类型或逐步转 TypeScript，兼容当前严格类型检查，不整体升级 Vue、Pinia、Vite。

## UI 适配

复用当前 `AppSidebar` 和应用布局，菜单名称为“电商宝盒”，建议放在“速创”后。按当前规则，普通用户使用创作入口，管理员通过现有模型、日志和积分管理能力管理服务。

样式直接使用当前设计变量：`--canvas`（#070b14）、`--surface-card`（#121a2b）、`--hairline`、`--body`、`--muted`、`--primary`（#6366f1）、`--brand-cyan`（#22d3ee）。字体沿用站内字体，正文 13-14px，区块标题 16-18px；表单、选择器、弹窗和图标优先复用 Element Plus 和当前图标注册表。

当前布局：

```text
站内菜单 | 电商宝盒  /  商品切换、新商品、保存状态、导入导出
         |-------------------------------------------------
         | 商品图片         | 成品批次、进度、暂停与继续
         | 制作内容、一句要求 | 主图 / 详情图 / 视频及改图
         | 更多配置（原位展开）| 打包下载、保存资产、详情长图
         |-------------------------------------------------
         | 成品数量、费用   |
         | 生成按钮         |
```

商品图片和结果是主要视觉内容。区块以分栏和分隔线组织；素材缩略图和结果项才使用重复卡片。当前选中图作为主要商品参考，其他上传图自动补充；指定模特与场景在可选设置中管理。已提交计划固定素材、风格和参数，不随继续填写而变化。

原项目三栏最小宽度合计约 1,000px，直接加入站内 280px 侧栏后会挤压常见笔记本屏幕。新页面桌面采用左侧创建、右侧成品两栏；900px 以下变为单页纵向滚动，上方创建、下方成品，不切换页签，主操作不遮挡内容。

风格控制只保留一个明确的套图主风格。站内画风与电商风格应按领域协调；摄影电商预设不与动漫等不兼容画风同时自动注入。用户私有模板和修改保存在个人项目内，不自动加入共享 Skill 匹配库。

## 后端与数据建议

建议新增独立电商 API 命名空间 `/api/ecommerce/*`，由当前认证中间件保护，具体接口保持项目现有 POST 风格。包含项目列表、新建、读取、保存、导入、创建套图计划、生成、状态、暂停后续、单项重做和结果管理。

建议数据边界如下，实际落库时再根据现有表结构确定是否合并：

| 数据 | 责任 |
| --- | --- |
| 电商项目 | 用户、名称、版本化配置、商品资料、当前选择、保存修订号；修订号防止多标签页覆盖 |
| 电商素材和结果 | 用户、所属项目、商品/模特/场景/成品角色、存储地址、版本、原请求与资产关联 |
| 生成计划 | 固定模型配置、商品事实、参考图顺序与用途、风格和每页规格；生成中编辑项目不改变已提交计划 |
| 逐项任务 | 页码或输出项、业务幂等键、状态、上游任务 ID、结果和 AI 日志关联、失败原因及时间 |

复用 `ModelConfigResolver`、`ImageGenerationOptions`、现有图片与视频调用适配器、`MediaStorage`、`CreditService` 和 `AiRequestLog`。目前速创本身也通过 `AssetController::callImageGeneration` 和 `SeriesController::callWorkflowVideoGeneration` 执行生成，可沿用这一适配方式，再按实际重复程度决定是否抽取公共服务。

电商任务不写成普通速创聊天记录。套图有 12-14 个输出，应在后台逐项执行，页面离开后任务仍能继续。执行器需要接入现有供应商并发控制，避免单个套图占满全站容量。

任务执行必须把新的电商任务记录接入“上游 ID 提交后立即保存”和状态恢复链路，不能只调用底层接口而遗漏其当前针对速创或资产任务的持久化上下文。积分和日志沿用统一链路，不在电商任务中重复扣费。

“暂停”默认完成当前已提交项并停止后续提交；已经提交上游的任务不能承诺取消或退费。失败、未知和成功分开显示，结果未知先核对原任务。删除本地结果不会逆转已产生的供应商费用。

## 积分展示

生成前按所选模型和全部待提交页展示费用并检查余额。普通 2.5 当前 2K 为 18 积分/张，因此 12 张套图为 216 积分，14 张为 252 积分；模特、商品提取和场景生成若另行调用模型，分别产生费用。

Official 显示预计用量并沿用实际结算；单页重做或微调计为新生成，查询状态和恢复原任务不应再次发起生成。视频价格使用现有时长和分辨率报价。这里只引用当前项目价格配置，不创建第二套计费规则。

## 旧数据与资源迁移

1. 旧工作区在浏览器 IndexedDB，无法由新服务器自动读取另一个站点的数据。用户先在原电商宝盒导出 JSON，再在新页面导入。
2. 导入时验证 schema、数量、字段、图片来源和原始请求；Data URL 图片解码后存入当前用户空间，并重写素材、结果、套图与请求快照中的引用。
3. 旧任务 ID 不能直接成为新系统任务或扣费依据。历史视频任务和活动套图任务在导入时清理，不恢复为新系统队列；嵌入 JSON 的图片转换为新存储地址。旧服务器的 `/uploads`、`/outputs`、`/assets` 路径及任意外部 URL 不能自动迁入，需先在旧项目嵌入图片或在新页面重新上传。
4. 内置风格和场景预览迁入模块专属资源目录，处理 `/admin/` 基路径；原项目缓存、日志、输出目录、环境文件和服务器凭据不随模块复制。

## 实施顺序与验收

1. **模块与数据基础。** 新菜单、路由、页面布局、项目 API、用户隔离、上传与保存；使用现有素材检查桌面和手机 UI。
2. **单图完整链路。** 商品提取与标记、模特、场景、结果选择、模型参数、费用预估、后台生成、刷新恢复及保存至资产。
3. **套图与编辑。** 固定计划、5+7/8/9 页面选择、继续未提交项、暂停后续、单页微调重做、版本、删除撤销和详情长图导出。
4. **视频与历史导入。** 接入当前视频审核与生成链路，复用电商分镜规则，完成旧工作区导入和回归验证。

复用原项目关于商品标记、提示词、引用顺序、套图固定与单页编辑的测试案例；将旧接口、文件任务和本机存储测试改为新协议测试。新增重点验收：跨用户访问被拒绝；页面刷新和 Worker 恢复不重复提交；扣费只发生一次；模型参数按普通/Official 区分；套图暂停不丢失当前项；私有项目不进入共享模板；旧审核按钮与旧接口依赖清除。

已完成上述功能实现与本地隔离验证。上线前需部署代码、构建前端并启动电商 Worker，再用实际账号和模型安排真实生成验收。

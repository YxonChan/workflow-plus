# 剧集节点工作流全链路回归测试用例

## 目标

这份回归用例用于覆盖剧集工作流里最容易反复出问题的交互链路，重点验证：

- 上游节点重跑后，下游节点状态、当前产物、页面展示、提示词预览是否同时失效
- 视频节点是否会错误复用旧 `video_jobs`、旧 `output_json`、旧提示词缓存
- 视频版本切换后，下游镜头是否按真实血缘恢复或失效
- “查看提示词”这类后台预取行为，是否会误弹全局错误消息
- 修改上游内容前，页面是否给出足够明确的影响提示，取消后是否完全不改数据

本轮测试默认只覆盖剧集工作流：

`input -> storyboard/text -> shot_process -> image -> video -> output`

系列拆集工作流不在本轮主回归范围内。

## 测试夹具

1. 固定使用隔离数据前缀 `__codex_node_interaction_test__`。
2. 固定测试账号 `user1 / 123456`。
3. 固定最小工作流节点顺序：
   `input`、`storyboard`、`shot_process`、`image`、`video`、`output`。
4. 至少准备 3 个镜头：
   镜头 1 用于父版本切换；
   镜头 2 用于链式依赖恢复/失效；
   镜头 3 用于验证无关镜头不被误伤。
5. 预置视频版本：
   镜头 1 有父版本 `A / B / C`；
   镜头 2 有 `child_A`，其 `parent_version_id -> A`；
   镜头 2 另有 `orphan_C`，其 `parent_version_id = null`，但 `meta_json.input_image_url = C.end_frame_url`；
   另准备一个时间接近但无真实血缘关系的旧版本，专门验证不会被误认领。
6. 预置图片版本：
   每个镜头至少 1 个已选中图片版本，用于验证图片节点失效时是否清空 `shots.image_url` 与 `shot_media_versions.is_selected`。
7. UI 预热状态：
   在执行失效类测试前，至少执行过一次：
   展开视频节点、点击“查看提示词”、切换镜头版本。
8. 自动化测试使用模拟成功 URL，不调用真实 AI 视频模型。
9. 手工 UI 回归不要求真实生成视频，但要求页面状态与数据库状态一致。

## 详细用例

### A. 基础链路

#### TC-01 准备工作流

- 目的：确认首次执行节点时自动初始化本集流程，只创建运行记录、不偷偷跑完所有节点。UI 已去掉「测试模式」按钮；兼容接口 `/api/episodes/prepare-workflow` 仍可只初始化。
- 步骤：打开测试剧集，直接执行第一个可运行节点；或调用 `/api/episodes/prepare-workflow`。
- 预期：
  - 生成 1 条 `workflow_run`
  - 各 `workflow_run_nodes` 全部存在
  - 整体状态为 `idle` / `queued` / 当前节点 `running`
  - 未手动执行的下游节点无产物
- 自动化：API + DB

#### TC-02 顺序执行到全成功

- 目的：确认基础 happy path 可走通，后续失效测试建立在可靠基线之上。
- 步骤：依次执行 `input`、`storyboard`、`shot_process`、`image`、`video`、`output`。
- 预期：
  - 每个节点完成后 `status=success`
  - 文本节点有 `raw_output/output_json`
  - 图片节点有 `shots.image_url`
  - 视频节点有 `shots.video_url/video_end_frame_url`
  - 输出节点有最终视频产物
- 自动化：API + DB，UI 抽查

#### TC-03 运行中防重复提交

- 目的：确认节点或镜头运行中不会重复发起任务。
- 步骤：
  - 让一个节点处于 `running`，连续点击“执行节点”
  - 让单镜头视频处于 `queued/running`，连续点击“生成这一段”
- 预期：
  - 页面只出现一次提交
  - 按钮进入 loading/禁用
  - 不会出现重复 `video_jobs`
- 自动化：UI + DB

#### TC-04 单镜头生成与整节点生成并存

- 目的：确认视频节点支持“只生成一个镜头”和“全部生成”。
- 步骤：先对单镜头执行一次生成，再对整个视频节点执行“全部生成”。
- 预期：
  - 对应镜头出现单独任务标记
  - 整节点执行不会覆盖无关镜头
  - `runningStageKeys` 与镜头级 busy 状态一致
- 自动化：UI

### B. 上游变更后的失效清理

#### TC-05 保存未改动的 plot_input

- 目的：确认无实际变更时不触发失效。
- 步骤：打开剧集详情，保持 `plot_input` 不变，点击保存。
- 预期：
  - 不出现“会影响下游”的警告
  - 下游节点状态、镜头产物、版本选择完全不变
- 自动化：UI

#### TC-06 修改 plot_input 但取消保存

- 目的：确认警告弹窗只提示，不应提前清空任何东西。
- 步骤：修改 `plot_input`，点击保存，在确认框中点取消。
- 预期：
  - 当前页面仍保留旧下游结果
  - 刷新后数据也不变
  - 无节点被重置
- 自动化：UI

#### TC-07 修改 plot_input 并确认保存

- 目的：确认最上游输入改动会让整条下游 current result 失效。
- 步骤：修改 `plot_input`，点击保存并确认。
- 预期 UI：
  - `storyboard` 到 `output` 全部回到 `queued/pending`
  - 展开文本节点不再显示旧内容
  - 视频节点不再显示旧镜头列表、播放器、版本数
  - 输出节点不再显示最终成片
- 预期数据：
  - 下游 `workflow_run_nodes.raw_output/output_json/error_message/started_at/finished_at` 清空
  - `shots.image_url/video_url/video_end_frame_url` 清空
  - 相关 `shot_media_versions.is_selected=0`
  - 未完成 `video_jobs` 被取消
  - 旧成功视频不再作为 current result
- 自动化：API + DB + UI

#### TC-08 重跑 input 节点

- 目的：确认从节点入口重跑，效果与修改 `plot_input` 一致。
- 步骤：在 `input` 已成功状态下点击“重新执行”，确认影响提示后执行。
- 预期：
  - `storyboard/shot_process/image/video/output` 全部失效
  - 当前镜头视频、图片、最终成片全部从页面消失
  - 只有历史版本记录保留
- 自动化：API + DB + UI

#### TC-09 更新 storyboard 节点内容

- 目的：确认中游文本变更只影响其下游，不误伤上游。
- 步骤：直接更新 `storyboard` 节点内容，或走“可编辑文本节点重跑”路径。
- 预期：
  - `input` 仍保留成功
  - `shot_process/image/video/output` 被清空并回到待处理
  - 镜头列表按最新 storyboard 重新定义
- 自动化：API + DB + UI

#### TC-09b 单镜改分镜保留历史成片

- 目的：改镜头 1 分镜后，当前成片清空，但历史视频版本（含当时 prompt）仍在版本库；`shot_key` 不变。
- 步骤：对「分镜处理」节点 `update-node-content`，`update_mode=single_shot`，`changed_shot_index=1`，并带上 `storyboard_shots[].shot_key`。
- 预期：
  - 镜头 1：`video_url` 空、`status=pending`、video versions 仍在且全未选中、prompt 保留
  - 镜头 2：当前视频仍在
  - 两端 `shot_key` 与改前一致
  - UI：意图条提示需重生成；历史成片库可打开旧片与旧提示词
- 自动化：API + DB；UI 手工

#### TC-10 更新 shot_process 节点内容

- 目的：确认镜头处理节点变更会清掉图片、视频、输出，但不清掉更早文本节点。
- 步骤：更新 `shot_process` 节点内容。
- 预期：
  - `input/storyboard` 保留成功
  - `image/video/output` 失效
  - 图片和视频 current result 清空
- 自动化：API + DB

#### TC-11 可选：重跑资产提取节点

- 目的：确认“重整资产”会影响后续引用，但不会删库式破坏资产本身。
- 步骤：仅在当前工作流包含资产提取节点时执行一次重跑。
- 预期：
  - 已有资产记录仍存在
  - 视频、图片、输出节点 current result 失效
  - 提示文案明确说明“已有资产不会被删除”
- 自动化：UI + DB

### C. 页面缓存、旧内容残留、提示词预览

#### TC-12 失效后再展开下一个文本节点

- 目的：验证后端已清空，但前端仍显示旧内容的问题。
- 步骤：先让 `storyboard`、`shot_process` 都成功并展开过；然后重跑上游；再点击展开这两个节点。
- 预期：
  - 节点正文为空或显示“暂无产物”
  - 不能再看到上一次生成的文本片段
- 自动化：UI

#### TC-13 失效后再展开视频节点

- 目的：验证视频节点不会继续拿旧 `output_json`、旧 `video_jobs`、旧 prompt cache 兜底展示。
- 步骤：先让视频节点成功、展开、选过镜头、切过版本、预览过提示词；再重跑上游；再展开视频节点。
- 预期：
  - 视频节点显示空状态
  - 不再看到旧镜头列表、旧播放器、旧首尾帧、旧版本数、旧提示词草稿
- 自动化：UI

#### TC-14 被动展开视频节点时无全局报错

- 目的：专门卡“展开节点就弹顶部错误”的问题。
- 步骤：在视频节点上游尚未就绪时，只展开视频节点，不点击“查看提示词”。
- 预期：
  - 页面顶部不出现全局 ElMessage 报错
  - 节点正常显示空状态或待生成状态
- 自动化：UI

#### TC-15 主动点击“查看提示词”但上游未就绪

- 目的：区分静默后台预取与用户主动查看。
- 步骤：在视频节点上游未就绪时，点击“查看提示词”。
- 预期：
  - 只出现一次明确、可理解的提示
  - 不会打开残留旧内容的预览框
  - 关闭后页面状态不脏
- 自动化：UI

#### TC-16 上游重新就绪后再查看提示词

- 目的：确认预览使用最新链路，不拿旧缓存。
- 步骤：重新跑通上游到可预览状态，再点“查看提示词”。
- 预期：
  - 预览镜头数、镜头顺序、每条 prompt、引用图信息，都与最新 `storyboard/shot_process/asset matching` 一致
- 自动化：UI + API

#### TC-17 切换剧集或切换节点后返回

- 目的：验证本地缓存不会跨剧集、跨节点串味。
- 步骤：在 A 剧集预览过视频提示词后切到 B，再切回 A；或者从视频节点切到别的节点再切回。
- 预期：
  - 只有当前 episode/current node 的合法预览内容会出现
  - 已失效节点不会复活旧 prompt
- 自动化：UI

### D. 视频版本切换与血缘恢复

#### TC-18 父版本切到无子版本的 B

- 目的：确认下游镜头应立即失效，而不是继续挂旧视频。
- 步骤：镜头 1 当前选中 `A`，镜头 2 当前跟随 `child_A`；把镜头 1 切到 `B`。
- 预期 UI：
  - 镜头 2 显示 `需重生成` 或空状态
  - 当前视频播放器清空
  - 不再显示 `child_A`
- 预期数据：
  - `shots.video_url/video_end_frame_url` 清空
  - 镜头 2 全部 `video` 版本 `is_selected=0`
  - 状态变 `pending/stale`
- 自动化：API + DB + UI

#### TC-19 切回父版本 A

- 目的：确认精确血缘能恢复，不需要重新生成。
- 步骤：从 `B` 切回 `A`。
- 预期：
  - 镜头 2 自动恢复 `child_A`
  - 页面立即显示对应视频与尾帧
  - 状态回已生成
  - 正确版本被重新选中
- 自动化：API + DB + UI

#### TC-20 切到父版本 C，命中 input frame orphan

- 目的：确认兼容补链逻辑仍有效。
- 步骤：把镜头 1 切到 `C`。
- 预期：
  - 镜头 2 恢复 `orphan_C`
  - 同时系统补写 `parent_version_id = C.id`
  - 页面显示恢复后的视频
- 自动化：API + DB

#### TC-21 禁止按 create_time 猜链路

- 目的：确认旧的模糊兜底不再误恢复。
- 步骤：存在一个与镜头 1 切换时间接近、但无真实血缘的旧视频版本；切到一个不应命中的父版本。
- 预期：
  - 镜头 2 保持空或 stale
  - 不会误选时间接近的旧版本
- 自动化：API + DB

#### TC-22 版本切换 UI 同步

- 目的：确认“上一版 / 下一版 / 版本记录弹层”三处入口一致。
- 步骤：在同一镜头依次用左右按钮切版，再打开版本记录弹层切到另一版。
- 预期：
  - 当前播放器、版本标签、镜头缩略卡、首尾帧、下游链路状态同步更新
  - 无需刷新页面
- 自动化：UI

#### TC-23 下游已经 stale 时继续切父版本

- 目的：确认 stale 状态下不会留下半残旧展示。
- 步骤：让镜头 2 先 stale；随后在镜头 1 的多个无子版本之间反复切换。
- 预期：
  - 镜头 2 始终保持空或 stale
  - 直到切到有精确血缘或 input-frame 精确匹配的父版本才恢复
- 自动化：UI + DB

### E. 输出节点与最终成片

#### TC-24 视频节点失效时输出节点同步失效

- 目的：确认最终成片也属于 current result，不能继续展示旧产物。
- 步骤：先让 `output` 成功；然后重跑 `input`、`storyboard` 或 `video` 上游。
- 预期：
  - `output` 节点回到 `queued/pending`
  - 最终成片从页面消失
  - 不会继续显示旧合成视频
- 自动化：API + DB + UI

#### TC-25 切换镜头视频版本后输出节点处理

- 目的：锁定版本切换对最终成片的影响。
- 步骤：在已经存在最终成片的前提下，切换任一镜头当前选中视频版本。
- 预期：
  - 输出节点应被视为过期
  - 当前最终成片从页面移除
  - 等待重新合成
- 自动化：UI + DB
- 默认：如果现有业务暂未支持自动标记 `output stale`，也必须记为缺口，不能误判为通过。

### F. 警告文案与取消保护

#### TC-26 成功节点重跑前的影响提示

- 目的：确认不是静默改数据。
- 步骤：对一个已成功的 `input/storyboard/shot_process` 节点点击“重新执行”。
- 预期：
  - 弹窗列出会影响的下游节点名
  - 列出当前受影响的图片数、视频数、输出数
  - 明确说明“旧产物会从当前结果中移除”
  - 取消后不发生任何状态变化
- 自动化：UI

#### TC-27 可编辑文本节点改 prompt 后再确认

- 目的：确认“先选提示词，再确认影响”的两段式交互正确。
- 步骤：打开可编辑文本节点的 rerun prompt dialog，切换模板或自定义 prompt，点击确认。
- 预期：
  - 先完成 prompt 选择
  - 再出现影响提示
  - 取消影响提示后，不应真的发起 rerun
- 自动化：UI

#### TC-28 忙碌态与锁定态保护

- 目的：确认生产中或锁定状态不会让测试过程本身引入脏写。
- 步骤：在节点 `running` 时重复点击；在 workflow locked 状态下点击保存、执行、版本切换。
- 预期：
  - 页面只给出阻止提示
  - 不产生额外请求
  - 不改变已有状态
- 自动化：UI

3. 现有 `scripts/test_workflow_node_interactions.php` 作为第一层骨架保留，并按本清单扩展：
   - 新增 `plot_input save` 路径
   - 新增 `update-node-content` 路径
   - 新增图片节点失效断言
   - 新增输出节点失效断言
   - 新增无 time-based fallback 断言
4. UI 自动化建议使用 Playwright，重点断言三类东西：
   - 节点状态文案
   - 产物区域是否为空
   - 是否出现不该出现的全局错误消息

## 默认约定

- 本轮测试默认只覆盖剧集工作流，不覆盖系列拆集工作流。
- 历史版本记录允许保留在数据库里；要求被清掉的是当前结果和当前选中版本，不是历史归档本身。
- 视频和图片自动化执行使用模拟成功 URL，不调用真实 AI 模型。
- 对于包含资产提取节点的工作流，执行 `TC-11`；不包含该节点可跳过。
- `output` 节点默认视为所有上游镜头当前版本的聚合结果；只要上游当前镜头或其版本发生变化，`output` 就应失效并从当前展示中移除。
